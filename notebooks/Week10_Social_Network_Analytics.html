Week 10 — Social Network Analytics¶

Who matters, who belongs together, and how does information spread?¶

SENG 42293 Big Data Analytics · LO3, LO4

Relationships are data too. A social network is a graph: nodes (travellers) and edges (who follows whom). Network analytics asks questions a table cannot: who is influential, which groups exist, how fast would a recommendation spread?

In this notebook: graph basics · degree and the long tail · centrality (degree, betweenness, PageRank) · community detection (Louvain) checked against known interests · PageRank by hand on Spark RDDs · information diffusion simulation.

Data: follows.csv (directed follower → followed) and traveller_profiles.csv (each traveller's main interest).

The network is synthetic, generated with four interest-based communities plus a few popular hubs, so we know the "right answer" for community detection.

3. Community detection with Louvain¶

Louvain groups nodes to maximise modularity: more edges inside groups than expected by chance. It works on an undirected graph. We know each traveller's true interest, so we can check the algorithm.

4. PageRank by hand: the algorithm that scales¶

PageRank is iterative: every node shares its current rank equally among the nodes it follows, then ranks are recomputed with damping d = 0.85:

PR(v) = (1 − d)/N + d · Σ PR(u)/outdeg(u) over followers u of v (plus a share of rank from dangling nodes).

This maps neatly to join → flatMap → reduceByKey on a cluster, which is how Google-scale graphs are processed (Pregel/GraphX use the same idea). First a small NumPy version, then Spark RDDs.

In [7]:
nodes = sorted(G.nodes); ix = {u: i for i, u in enumerate(nodes)}
def pagerank_np(G, d=.85, iters=50):
    N = len(nodes); r = np.full(N, 1 / N)
    for _ in range(iters):
        new = np.full(N, (1 - d) / N); dangling = 0
        for u in nodes:
            out = list(G.successors(u))
            if out:
                for v in out: new[ix[v]] += d * r[ix[u]] / len(out)
            else: dangling += r[ix[u]]
        new += d * dangling / N; r = new
    return pd.Series(r, index=nodes)
pr_np = pagerank_np(G)
print("max |manual - networkx| =", float((pr_np - pr.reindex(nodes)).abs().max()))
RES["pr_manual_err"] = float((pr_np - pr.reindex(nodes)).abs().max())

import sys; os.environ["PYSPARK_PYTHON"] = sys.executable
from pyspark.sql import SparkSession
spark = SparkSession.builder.master("local[4]").config("spark.ui.enabled", "false").config("spark.default.parallelism", "4").getOrCreate(); sc = spark.sparkContext; sc.setLogLevel("ERROR")
lines = sc.textFile("data/follows.csv", 4); header = lines.first()
edges = lines.filter(lambda l: l != header).map(lambda l: tuple(l.split(",")))
links = edges.groupByKey(4).mapValues(list).cache(); links.count()                # node -> accounts it follows
allnodes = edges.flatMap(lambda e: e).union(sc.parallelize(nodes, 4)).distinct(4).cache()
N = allnodes.count(); ranks = allnodes.map(lambda u: (u, 1.0 / N)); d = .85
for _ in range(15):
    contribs = links.join(ranks).flatMap(lambda kv: [(v, kv[1][1] / len(kv[1][0])) for v in kv[1][0]])
    dangling = ranks.subtractByKey(links).values().sum()                                     # rank held by nodes that follow nobody
    summed = contribs.reduceByKey(lambda a, b: a + b, 4)
    ranks = allnodes.map(lambda u: (u, 0.0)).leftOuterJoin(summed).mapValues(lambda t: (1 - d) / N + d * ((t[1] or 0.0) + dangling / N)).cache()
    ranks.count()                                                                              # materialise so lineage does not grow
spark_pr = pd.Series(dict(ranks.collect()))
err = float((spark_pr.reindex(nodes) - pr_np).abs().max()); print(f"nodes = {N}; max |Spark - manual NumPy| = {err:.2e}; ranks sum to {spark_pr.sum():.4f}")
print("Spark top-3:", spark_pr.sort_values(ascending=False).head(3).round(4).to_dict()); RES["pr_spark_err"] = err
spark.stop()

5. Information diffusion: does the seed choice matter?¶

Simulate an independent cascade: a seed traveller shares a recommendation; each follower adopts with probability p; adopters share onward. Compare seeding with a random traveller, the most-followed one, and the top PageRank one (average of 300 runs, p = 0.12).

In [9]:
rng = np.random.default_rng(5)
rev = G.reverse(copy=False)                         # information flows to followers: edge v -> u when u follows v
def cascade(seed, p=.12):
    active, frontier = {seed}, [seed]
    while frontier:
        nxt = []
        for v in frontier:
            for u in rev.successors(v):
                if u not in active and rng.random() < p: active.add(u); nxt.append(u)
        frontier = nxt
    return len(active)
def avg(seed_fn, runs=300): return float(np.mean([cascade(seed_fn()) for _ in range(runs)]))
nodes_l = list(G.nodes); best_deg = indeg.idxmax(); best_pr = pr.idxmax()
res = {"random traveller": avg(lambda: nodes_l[rng.integers(len(nodes_l))]), "most followed": avg(lambda: best_deg), "top PageRank": avg(lambda: best_pr)}
for k, v in res.items(): print(f"{k:18s} mean reach = {v:6.1f} travellers ({v / n:.1%})")
RES["diffusion"] = {k: round(v, 1) for k, v in res.items()}
fig, ax = plt.subplots(figsize=(6, 3.4)); ax.bar(res.keys(), res.values(), color=[GREY, ACC, CH]); ax.set_ylabel("mean travellers reached"); ax.set_title("Reach of a recommendation by seed choice (p = 0.12)"); save("w10_diffusion")

Seeding a well-connected node reaches more people than seeding a random one, which is the logic behind influencer marketing. But reach also depends on p: below a threshold, cascades die out regardless of the seed. Try p = 0.05 and 0.25 in the exercises.

6. Limits and ethics¶

  • Sampling bias: you rarely see the whole network; metrics change when edges are missing.
  • Correlation, not causation: friends are similar because of influence or because similar people connect (homophily).
  • Privacy: graph structure can re-identify "anonymous" users; handle with care and consent.
  • Scale: all-pairs measures (betweenness) are O(n·m); use sampling (k=200 above) or approximations.
